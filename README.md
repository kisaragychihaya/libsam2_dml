# libsam2_dml

SAM2 (Hiera-Small) segment-anything inference on **ONNX Runtime + DirectML**, packaged as a
single C-ABI DLL plus a **pure-Go** (no cgo) example client.

`sam2_dml.dll` owns two ONNX Runtime sessions — the SAM2 image encoder (1024x1024 input) and the
mask decoder — both attached to `DmlExecutionProvider`. It takes a raw RGB24 buffer and a point
prompt and hands back low-resolution mask logits plus IoU predictions. Buffers are owned by the
DLL, handles are internally serialized with a mutex, and every failure is reported through a
thread-local ASCII error string, so the DLL can be driven from any language with a plain C FFI.

The example client (`example/`) is the reason this repo is not just a header: it loads the DLL
with `syscall.NewLazyDLL` under `CGO_ENABLED=0`, times both stages, dumps logits, and cross-checks
them against a Python/`onnxruntime-directml` reference — the same check CI runs.

- 100% Go client, zero cgo, no C toolchain needed to consume the DLL
- Windows x64 only (DirectML), Release build, `/MD` runtime
- Deterministic synthetic test image generated by the tool itself (no sample photo needed)
- CI: build + DirectML QC, manually triggered, `atol=1e-3` gate against the Python reference

## Release assets (v0.1.0)

| Asset | What it is |
| --- | --- |
| `libsam2_dml-v0.1.0-win-x64.zip` | `sam2qc.exe` + `sam2_dml.dll` + `onnxruntime.dll` + `DirectML.dll` + example sources + README summary. Unpack and run. |
| `sam2_dml.dll` | The library (C ABI in `native/include/sam2_dml.h`). Needs the two DLLs below next to it. |
| `onnxruntime.dll` | ONNX Runtime **1.24.4** (DirectML build, x64). |
| `DirectML.dll` | Microsoft.AI.DirectML **1.15.4**. |
| `sam2_hiera_small.encoder.onnx` | SAM2 Hiera-Small image encoder, 1024x1024 RGB float32 in, `high_res_feats_0` / `high_res_feats_1` / `image_embed` out (155 MB). |
| `sam2_hiera_small.decoder.onnx` | SAM2 Hiera-Small mask decoder, points/labels/embeddings in, mask logits + IoU out (20 MB). |

The two `.onnx` files are too large for git (>100 MB) and are published as release assets only.
`native/third_party/fetch_ort_dml.py` re-downloads the ONNX Runtime DirectML and DirectML NuGet
packages (`1.24.4` / `1.15.4`) to make the native build reproducible.


## C API

Full contract and field semantics: [`native/include/sam2_dml.h`](native/include/sam2_dml.h).

```c
const char*          sam2_get_last_error(void);

sam2_encoder_t*      sam2_encoder_create(const char* model_path_utf8, int device_id);
void                 sam2_encoder_destroy(sam2_encoder_t*);
const char*          sam2_encoder_provider(const sam2_encoder_t*);   // "DmlExecutionProvider" / "CPUExecutionProvider"
sam2_embedding_t*    sam2_encoder_encode(sam2_encoder_t*, const unsigned char* rgb,
                                         int width, int height, int stride);
void                 sam2_embedding_destroy(sam2_embedding_t*);

sam2_decoder_t*      sam2_decoder_create(const char* model_path_utf8, int device_id);
void                 sam2_decoder_destroy(sam2_decoder_t*);
const char*          sam2_decoder_provider(const sam2_decoder_t*);

/* points_xy: [n][2] image pixels; labels: 1=positive, 0=negative, 2=box TL, 3=box BR */
sam2_decode_result_t* sam2_decoder_decode(sam2_decoder_t*, const sam2_embedding_t*,
                                          const float* points_xy, const int32_t* labels,
                                          int32_t n_points);
void                 sam2_decode_result_destroy(sam2_decode_result_t*);
```

```c
typedef struct {
    float*  masks;      /* [num_masks][mask_h][mask_w] float32 logits */
    float*  iou;        /* [num_masks] float32 */
    int32_t num_masks;
    int32_t mask_h;     /* 1/4 of the encoder size, i.e. 256 */
    int32_t mask_w;
} sam2_decode_result_t;
```

Notes that matter for FFI clients:

- `sam2_decode_result_t` is 32 bytes on x64 with `num_masks/mask_h/mask_w` at offsets 16/20/24.
  `example/main.go` asserts size and offsets in `checkLayout()` before calling anything.
- All returned pointers are owned by the DLL; free them with the matching `*_destroy` function.
- `sam2_encoder_create()` performs one dummy warmup inference, so the first real encode is not
  charged for DirectML graph compilation. Same for `sam2_decoder_create()`.
- Handles are thread-safe but serialized: concurrent calls on the same handle run one at a time.
- Preprocessing is fixed to the anylabeling/SAM2 recipe: half-pixel bilinear resize to 1024x1024,
  `/255`, ImageNet mean/std, NCHW float32. No other preprocessing is available through this ABI.

## Build from source (Windows x64)

Requirements: Visual Studio 2022 (MSVC v143, any edition), CMake ≥ 3.20, Ninja, Python 3.8+,
Git Bash. `build.sh` finds `vcvars64.bat`, `cmake` and `ninja` through `vswhere` or PATH; you can
pin them with `VCVARS=`, `CMAKE=`, `NINJA=`.

```bash
python native/third_party/fetch_ort_dml.py     # ORT-DML 1.24.4 + DirectML 1.15.4 (~240 MB, cached)
./native/build.sh                              # -> native/build/sam2_dml.dll + runtime DLLs
```

Equivalent manual steps:

```bat
python native\third_party\fetch_ort_dml.py
cmake -S native -B native\build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build native\build
```

`native/build/` then contains `sam2_dml.dll`, `onnxruntime.dll`, `DirectML.dll` and
`onnxruntime_providers_shared.dll`. Keep the DLLs together — the loader resolves them from the
directory of `sam2_dml.dll`, and no `PATH` change is required.

## Go example (CGO_ENABLED=0)

Drop the release assets next to each other:

```
bin/sam2qc.exe
bin/sam2_dml.dll
bin/onnxruntime.dll
bin/DirectML.dll
sam2_hiera_small.encoder.onnx     (or point SAM2_ENCODER at it)
sam2_hiera_small.decoder.onnx
```

Then, from the repo root:

```bash
./example/run_qc.sh                     # builds the exe, generates the test image, runs the QC pass
./example/run_qc.sh path/to/photo.jpg   # any of your own images instead
```

`run_qc.sh` builds with `CGO_ENABLED=0 go build -trimpath` and stages the three DLLs next to the
exe. Model paths default to the repo root; DLL/model paths can be overridden:

| Env var | Meaning | Default |
| --- | --- | --- |
| `SAM2_DLL` | path to `sam2_dml.dll` | next to `sam2qc.exe` |
| `SAM2_ENCODER` | encoder ONNX | next to the exe, then one/two dirs up (repo root) |
| `SAM2_DECODER` | decoder ONNX | same |
| `SAM2_DEVICE` | DirectML adapter index | `0` |
| `SAM2_RUNS` | timed iterations per stage | `5` |
| `SAM2_ALLOW_CPU` | continue with a warning instead of failing when DirectML is unavailable | unset (non-DML is a failure) |
| `SAM2_MODEL_DIR` | where `run_qc.sh`/`crosscheck.sh` look for the models | repo root |

The QC binary takes one image and writes into the current directory:

| File | Content |
| --- | --- |
| `go_logits.bin` | `"S2LOGITS"` + `int32 num_masks, mask_h, mask_w` + float32 logits, little endian |
| `go_rgb.bin` | `"S2RGB123"` + `int32 width, height` + exact RGB24 bytes fed to the encoder |
| `mask_output.png` | best mask (`logit > 0`) as a grayscale PNG at input resolution |

Usage of the binary itself:

```bash
sam2qc.exe --gen-test-image out/test_image.png   # deterministic synthetic 640x480 PNG
sam2qc.exe out/test_image.png                    # QC pass (exits non-zero on failure)
```

`--gen-test-image` draws a two-axis gradient with a circle, a rectangle, a triangle and a faint
hatch, using integer math only — the bytes are identical on every machine, so it is a valid
regression input without shipping a photograph. Your own photos are still fine: pass one as the
positional argument.

Loading the DLL is plain `syscall` (see `example/main.go`):

```go
dll := syscall.NewLazyDLL(`C:\path\to\sam2_dml.dll`)
create := dll.NewProc("sam2_encoder_create")
p, _ := syscall.BytePtrFromString(`C:\path\to\sam2_hiera_small.encoder.onnx`)
enc, _, _ := create.Call(uintptr(unsafe.Pointer(p)), 0) // device_id 0
```

## QC

`./example/run_qc.sh` is the whole end-to-end check:

1. builds the Go client with `CGO_ENABLED=0`
2. generates the synthetic test image if none is given
3. creates encoder + decoder, **fails unless both report a provider containing `Dml`**
4. one warmup call, then `SAM2_RUNS` timed encodes and decodes
5. dumps logits/RGB and renders `mask_output.png`

`./example/crosscheck.sh` adds the numerical check against `onnxruntime-directml` (install it with
`python -m pip install onnxruntime-directml pillow numpy`). Both sides run the *same* preprocessing
(half-pixel bilinear, `/255`, ImageNet mean/std), the same center-point prompt, zero `mask_input`
and `has_mask_input=0`, and the Go logits are compared with `atol=1e-3`:

| Pair | Kind | Typical max abs diff |
| --- | --- | --- |
| `go_logits.bin` vs `ref_logits_gorxgb.bin` (same pixels the DLL saw) | gate | 0 – 3e-5 |
| `go_logits_png.bin` vs `ref_logits_png.bin` (same PNG, both decoders) | gate | 0 – 3e-5 |
| `go_logits.bin` vs `ref_logits_src.bin` (input decoded per side) | diagnostic | 0 for PNG input, up to ~1 for JPEG |
| `go_logits.bin` vs `ref_logits_pil.bin` (PIL resize kernel) | diagnostic | ~3e-1 |

Reference numbers on a discrete NVIDIA GPU (816x922 JPEG, 5 runs each): `encoder_create` ~1.2 s,
encode min/avg/max 138.8 / 148.0 / 162.8 ms, `decoder_create` ~0.8 s, decode 9.2 / 10.3 / 11.2 ms,
binary IoU between Go and Python masks 1.0.

### CI

`.github/workflows/build-and-qc.yml` is `workflow_dispatch` only. On `windows-latest` it fetches
ORT-DML, builds the DLL with MSVC + CMake + Ninja, builds the Go client with `CGO_ENABLED=0`,
downloads both models (URLs are inputs, defaults point at this repo's `v0.1.0` assets), generates
the synthetic image, runs the QC pass, asserts `DmlExecutionProvider`, then runs `ref_dump.py` +
`compare.py` with `atol=1e-3` (a failing comparison fails the job) and uploads a single
`dist-<version>.zip` artifact containing just `bin/` (exe + DLLs). Inputs: `encoder_url`, `decoder_url`,
`runs` (default 2), `require_dml`, `version` (zip suffix; empty defaults to `git describe --tags`)
(default true — a DirectML fallback to CPU fails the job rather than silently passing). Before the QC
pass it inventories the runner's display adapters and probes `SAM2_DEVICE=0..3`, so a DirectML device
reachable only at another adapter index is still found.

About the WARP case: hosted runners have no GPU, and DirectML is *supposed* to fall back to the WARP
software adapter there (which would still report `DmlExecutionProvider`, just slower). On the
`windows-latest` image it cannot: the only display controller is `Microsoft Hyper-V Video`, which has
no D3D12 support, so DirectML device creation fails with `Specified display adapter handle is
invalid` for every adapter index. That is an environment limit, not a library bug — the DLL reports
`CPUExecutionProvider`, keeps the DirectML failure text in `sam2_get_last_error()`, and the job fails
while `require_dml=true`. `require_dml=false` keeps the numerical cross-check alive on CPU
(`SAM2_ALLOW_CPU=1`) and the log always states which provider actually ran.

Latest manual run:
**[run 45179978766](https://github.com/kisaragychihaya/libsam2_dml/actions/runs/45179978766) — success,
all 18 steps green**, artifact `sam2_dml-win-x64-qc`. What it actually measured:

for DirectML here.

## Known caveats

- **Deprecated DirectML append API.** `native/src/sam2_dml.cpp` uses the free function
  `OrtSessionOptionsAppendExecutionProvider_DML(options, device_id)`. ONNX Runtime marks this
  family deprecated in favour of the session-options method
  (`options.AppendExecutionProvider("DML", {{"device_id", ...}})`); it is still compiled and
  exported by `onnxruntime.dll` 1.24.4 and behaves identically, but expect warnings when moving to
  a newer ORT and plan the migration.
- **JPEG decoders disagree.** Go's `image/jpeg` and libjpeg differ by up to ~14 LSB per channel on
  the same file, which moves the logits by ~1 — far more than any DLL defect. Feed PNG, or compare
  `go_rgb.bin` (the exact pixels the DLL saw), if you need a tight numerical gate. The synthetic
  test image is a PNG for this reason.
- **No GPU / WARP.** On a machine without a discrete GPU, DirectML can still run on the WARP
  software adapter (still reported as `DmlExecutionProvider`), but encode times go from ~140 ms to
  seconds. It only works if the adapter DirectML is pointed at actually supports D3D12 — a Hyper-V
  synthetic display adapter, for example, does not, and DirectML device creation then fails with
  `Specified display adapter handle is invalid` (measured on GitHub's `windows-latest` runners). In
  that case the DLL falls back to `CPUExecutionProvider`, keeps the DirectML failure text in
  `sam2_get_last_error()`, and `sam2_encoder_provider()`/`sam2_decoder_provider()` tell you which
  provider is live. The QC client deliberately treats a non-DML provider as a failure unless
  `SAM2_ALLOW_CPU=1` is set explicitly.
- **Fixed preprocessing, fixed encoder size.** 1024x1024, ImageNet normalization, bilinear resize,
  no batching, single encoder per handle. Changing any of that requires a matching ONNX export.
- **x64 Windows only.** The build is MSVC `/MD` against `onnxruntime.dll`; the Go client needs
  Windows because it drives `syscall.NewLazyDLL`.
